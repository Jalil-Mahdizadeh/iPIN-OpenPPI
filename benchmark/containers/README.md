# Benchmark containers

All new candidate-specific SIF images, recipes, manifests, logs, build caches, and temporary build files belong under this directory, not the repository's existing `containers/` directory. This resolves the instruction to use a containers folder while keeping every new artifact inside `benchmark/`.

An existing repository SIF may be used read-only only after dependency, ARM64/GPU, and candidate numerical qualification. If it is insufficient, build a separately versioned candidate image here; never install into or overwrite the existing images. Images are generated, ignored artifacts.

TUnA's existing base lacked `fair-esm`, `uncertainty-calibration`, and `h5py`, so a separate image was built successfully using [build_tuna.sh](build_tuna.sh) and [tuna-arm64-v1.def](tuna-arm64-v1.def). The final SHA-256 is `98070c7c2d206d8421817849e11ffce308016dc982938a7d9a3ef3141ab1dec1`. Build manifests are in `manifests/`; qualification is recorded in the [TUnA report](../tuna/REPORT.md).
